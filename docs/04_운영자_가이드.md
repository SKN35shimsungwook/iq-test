# 04. 운영자 가이드

## 1. 관리자 페이지 들어가기

- 상단 메뉴 **관리 → 분석**. 비밀번호는 Secrets의 `admin_password` 값입니다.
  - 로컬: `.streamlit/secrets.toml` (git에 올라가지 않음)
  - 배포: Streamlit Cloud 앱 설정 → Secrets
- 맨 위 **저장소** 표시를 먼저 확인하세요. 배포 환경에서 `SQLite`로 나오면 재시작할 때 데이터가 사라집니다 ([4절](#4-supabase-연결)).
- **검사 방식**(전체/빠른/정밀)으로 거르고, **시뮬레이션 데이터 포함**을 켜면 가상 응시 데이터도 함께 봅니다.
- 데이터는 2분마다 다시 읽습니다. 바로 반영하려면 **새로고침**.

## 2. 화면별 해석

### 개요
| 지표 | 보는 법 |
|---|---|
| 시작한 검사 / 완료 / 완료율 | 완료율이 낮으면 검사가 너무 길거나 어딘가에서 막히는 것 |
| 규준에 쓰이는 첫 응시 | 같은 모드에서 이 수가 **100명**을 넘으면 결과의 "상위 %"가 실제 분포 기준으로 바뀜 |
| 소요 시간 중앙값 | 안내한 시간(빠른 15분·정밀 35분)과 크게 다르면 제한시간·문항 수 조정 검토 |
| 평균 탭 이탈 | 높으면 검색 등 부정행위 가능성. 개인 결과에도 표시됨 |
| 점수 분포 | 평균 100·표준편차 15 근처가 정상. 크게 벗어나면 문항 난이도 가정(예상 정답률)이 실제와 다른 것 → 보정값 적용 |

### 문항 분석
응답이 **30개 이상**인 문항만 판정합니다.

| 판정 | 기준 | 조치 |
|---|---|---|
| 너무 쉬움 | 실제 정답률 > 90% | 문항을 어렵게 고치거나 교체 |
| 너무 어려움 | 실제 정답률 < 10% | 문항 오류(정답·보기)부터 확인, 아니면 교체 |
| 변별도 낮음 | 정답 여부와 응시자 능력의 상관 < 0.2 | 잘하는 사람도 틀리고 못하는 사람도 맞힌다는 뜻 → 답이 애매하거나 찍기로 풀리는지 점검 |
| 예상보다 쉬움 / 어려움 | 실제 − 예측 정답률이 0.15 넘게 차이 나고 통계적으로도 뚜렷함(\|z\|>3) | 문항은 좋을 수 있음 → **보정값**을 적용해 채점에 실제 난이도를 반영 |
| 데이터 부족 | 응답 30개 미만 | 더 기다림 |

**예측 정답률**은 "그 문항을 실제로 본 사람들의 능력이라면 이 정도 맞혔어야 한다"는 값입니다.
1·2·3차는 모두 같은 구성이지만 심층검사는 실력에 맞춰 문항을 고르므로, 단순 정답률만 보면 어려운 문항이
쉬워 보입니다. 그래서 두 값을 비교합니다.

### 신뢰도
| 지표 | 기준 |
|---|---|
| 주변 신뢰도 (종합·영역별) | 0.8 이상: 개인 비교에 쓸 만함 / 0.7 미만: 참고용. 빠른 검사 영역 점수는 0.5 안팎이 정상(문항이 4개) |
| 동형 검사 신뢰도 (1·2차 상관) | 같은 사람이 겹치지 않는 문제로 두 번 푼 점수의 상관. 0.8 이상이면 양호 (연습 효과가 섞여 있어 참고용) |

### 차수·심층검사
- **차수별 진행**: 1차만 / 2차까지 / 3차까지 / 심층검사까지 한 사람 수
- **심층검사**: 영역별 평균 문항 수와 최종 오차. 평균 문항 수가 최대(6)에 가까우면 그 영역에 해당 실력대 문항이 부족하다는 뜻 → 그 난이도의 슬롯·동형을 늘림

### 내보내기
- **응답 CSV / 세션 CSV**: 원자료 (엑셀에서 바로 열림, UTF-8 BOM)
- **보정값 JSON**: 응답 50개 이상인 문항의 난이도(irt_b)를 실제 응답으로 다시 추정한 값

## 3. 문항 관리 절차

### 3-1. 문항 하나를 고치거나 교체
1. 관리자 페이지에서 문항 ID 확인 (예: `gc-synonym-3d`, `gf-matrix-4b`)
2. 직접 쓴 문항(`items/gc.json`, `items/gq.json`): 해당 항목을 고치고 **`version`을 1 올림**
   - 응답 로그에 버전이 함께 저장되므로, 고치기 전·후 응답을 구분해 분석할 수 있습니다.
3. 생성 문항(`items/generated.json`): 슬롯 단위로 생성되므로 개별 수정 대신 생성기 규칙이나 `forms` 수를 조정 ([05. 개발자 가이드](05_개발자_가이드.md))
4. 검증과 테스트를 통과시킨 뒤 커밋·푸시
   ```bash
   python scripts/validate_items.py --strict
   python -m pytest -q
   ```
5. 검토용 화면으로 눈으로 확인: `python scripts/render_review.py` → `review/items_review.html`

### 3-2. 보정값 적용 (데이터 기반 난이도)
1. 관리자 페이지 → 내보내기 → **보정값 JSON** 다운로드
2. 파일 이름을 `calibration.json`으로 바꿔 `items/` 폴더에 넣기
3. 커밋·푸시하면 채점이 예상 정답률 대신 이 값을 씀
4. 보정은 현재 능력 추정치를 기준으로 한 1차 근사이므로, 데이터가 더 쌓이면 다시 받아 덮어씀

### 3-3. 규준
- 규준은 **같은 모드 · 1차 검증 · 첫 응시 · 시뮬레이션 아님** 세션만으로 만듭니다.
- 100명 미만이면 문항 예상 정답률로 만든 가정 규준을 씁니다. 결과 화면 하단에 어느 기준인지 표시됩니다.

## 4. Supabase 연결

현재 배포는 SQLite(임시 저장)를 씁니다. 응시 기록을 계속 보관하려면 Supabase를 연결합니다.

1. https://supabase.com → New project, Region **Northeast Asia (Seoul)**, DB 비밀번호 따로 보관
2. 상단 **Connect → Session pooler** URI 복사 (Direct connection은 IPv6 전용이라 Streamlit Cloud에서 안 됨)
3. URL 고치기: `postgresql://` → `postgresql+psycopg2://`, 비밀번호 특수문자 URL 인코딩(`@`→`%40`, `#`→`%23`, `/`→`%2F`), 끝에 `?sslmode=require`
4. 로컬에서 점검
   ```bash
   python scripts/check_db.py "postgresql+psycopg2://postgres.<ref>:<비밀번호>@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres?sslmode=require"
   ```
   `통과`가 나오면 됩니다. 점검용 행은 스스로 지웁니다.
5. Streamlit Cloud → 앱 설정 → Secrets에 추가
   ```toml
   admin_password = "<긴 비밀번호>"

   [connections.sql]
   url = "postgresql+psycopg2://postgres.<ref>:<비밀번호>@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres?sslmode=require"
   ```
6. 저장하면 앱이 재시작되고, 테이블과 **RLS(행 단위 보안)** 가 자동으로 만들어집니다.
   RLS가 켜져 있어 Supabase 공개 API(anon 키)로는 응시 데이터를 읽거나 쓸 수 없습니다.
7. 관리자 페이지 상단이 **저장소: Postgres**로 바뀌었는지 확인

> 연결 전 SQLite에 쌓인 데이터를 옮기려면 연결 **전에** 관리자 페이지에서 응답·세션 CSV를 받아 두세요.
> 가져오기 스크립트는 아직 없으므로 필요하면 그때 만듭니다.

## 5. 배포와 장애 대응

### 배포
- 레포: `SKN35shimsungwook/iq-test` (비공개), 메인 파일 `streamlit_app.py`, Python 3.12~3.13
- **main에 푸시하면 자동 재배포**됩니다. SQLite 사용 중이면 재배포 때 데이터가 초기화됩니다.
- 비공개 레포로 만든 앱은 기본 비공개입니다. 다른 사람이 응시하려면 앱 **Share** 설정에서 공개로.
- 자세한 체크리스트: [DEPLOY.md](../DEPLOY.md)

### 자주 나는 문제
| 증상 | 원인 | 해결 |
|---|---|---|
| 푸시 직후 `ImportError` (예: `DEEP_ROUND`를 못 찾음) | Cloud가 바뀐 파일 일부만 다시 읽어 옛 모듈이 메모리에 남음 | **Manage app → ⋮ → Reboot app** |
| 관리자 페이지 "저장소: SQLite" | Secrets에 `[connections.sql]`이 없거나 형식 오류 | Secrets 확인, `check_db.py`로 URL 점검 |
| 처음 접속이 수십 초 걸림 | Community Cloud 앱이 잠들었다 깨어나는 중 | 정상 |
| Supabase 접속 실패 | 무료 플랜은 1주일 넘게 요청이 없으면 일시 정지 | 대시보드에서 다시 켜기 (데이터는 유지) |
| "관리자 비밀번호를 설정하면…" 안내만 보임 | `admin_password` 미설정 | Secrets에 추가 |

## 6. 시뮬레이션 데이터 (로컬 개발용)

```bash
python scripts/simulate.py --n 400        # 가상 응시자 400명 (기본: 로컬 SQLite)
python scripts/simulate.py --reset        # 시뮬레이션 데이터만 삭제
python scripts/simulate.py --n 100 --url "postgresql+psycopg2://..."   # 다른 DB에 (점검용)
```

- 능력이 정규분포인 가상 응시자가 실제 출제 로직으로 풀고, 일부는 2·3차와 심층검사까지 이어 풉니다.
- 문항 12개의 참 난이도를 일부러 크게 틀어 놓아, 문항 분석이 그런 문항을 찾아내는지 확인할 수 있습니다.
- `app_version="sim"`으로 저장되어 **규준에는 절대 들어가지 않고**, 관리자 화면에서도 기본으로 숨겨집니다.
- **배포 DB에는 넣지 마세요.**
