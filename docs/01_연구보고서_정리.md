## 2. 다섯 보고서의 공통 결론

1. **숫자를 만드는 건 쉽고, 그 숫자를 IQ라고 부를 근거를 만드는 게 어렵다.**
   "40문제 중 32개 정답 → IQ 120"은 공식 IQ가 아니다. 규준(비교 집단), 신뢰도, 타당도, 표준화된 절차가 있어야 한다.
2. **단계적으로 간다.** IQ 스타일 테스트 → 응답 데이터로 문항 분석·개선 → (연구기관 수준의) 표준화 검사.
3. **측정 영역은 CHC 이론을 따른다.** 유동추론(Gf), 결정지능/언어(Gc), 작업기억(Gwm), 시공간(Gv), 처리속도(Gs), 수리(Gq).
4. **점수는 편차 IQ(평균 100, 표준편차 15)** 로 바꾸고, 백분위와 영역별 점수, 오차 범위를 함께 준다.
5. **문항반응이론(IRT)과 컴퓨터 맞춤형 검사(CAT)** 가 현대적 방법이다. 문항마다 난이도·변별도·추측도를 두고,
   응시자 능력(θ)에 가장 정보가 많은 문항을 골라 낸다.
6. **기존 상용 검사 문항(WAIS·레이븐 등)은 저작권 때문에 쓸 수 없다.** 문항은 직접 만들어야 한다.
7. **개인정보**: 동의 체크박스는 기본값 해제, 필수·선택 동의 분리, 만 14세 미만은 법정대리인 동의.

## 4. 반영하지 않은 것과 이유

| 보고서의 권고 | 결정 | 이유 |
|---|---|---|
| 표준화 표본 N≥1,000, 연령별 규준 | 하지 않음 | 개인 프로젝트 범위를 넘음. 대신 실제 응시자 100명이 넘으면 그 분포로 자동 재표준화 |
| 개인정보(연령·성별) 수집 | 하지 않음 (완전 익명) | 개인정보 부담 최소화. 그 대신 연령별 규준은 만들 수 없음 |
| 회원가입·로그인 | 하지 않음 | 익명 브라우저 ID(localStorage)로 재응시만 구분 |
| 신분증·얼굴 인식, AI 감독 | 하지 않음 | 공식 검사가 아니므로 과도함 |
| React + FastAPI 구조 | Streamlit 단일 앱 | 빠른 개발과 배포. 정밀 타이밍이 필요한 부분만 커스텀 컴포넌트로 |
| 보고서 2의 예시 문항 20개 | 쓰지 않음 | 2번(문장과 보기 불일치), 7번(성립하지 않는 논리), 9번(지폐 계산이 나누어떨어지지 않음), 12번(윷놀이판, 의미 불명), 19번(글자 세기, 의미 불명) 등 오류가 있어 전부 새로 작성 |
| "IQ"라는 이름 그대로 사용 | 자체 지수(LTR Index) + IQ 척도 환산치 병기 | 규준 데이터가 없는 상태에서 공식 IQ로 오해되지 않게. 결과에서는 "IQ (LTR Index)"로 함께 표시 |
| 처음부터 CAT | 1·2·3차는 고정 구성, 심층검사만 CAT | 사용자 요청: 1·2·3차는 같은 형식으로 비교하고, 심층검사에서 정밀하게 |

## 5. 보고서별 참고할 만한 부분

- **보고서 1**의 검사 비교표는 결과 화면의 "IQ 구간 해석"(130 이상 매우 우수 등)과 정규분포 설명의 근거입니다.
- **보고서 4**의 CAT 파이프라인(초기 θ=0, 최대 피셔 정보량 선택, EAP 추정, SEM 종료)이 심층검사 알고리즘의 원형입니다.
  다만 초기 θ는 0이 아니라 1~3차 응답으로 추정한 값에서 출발합니다.
- **보고서 5**의 "개발 전 핵심 질문 24개"는 기획 단계 질의응답의 틀로 썼습니다 ([02. 개발 과정](02_개발과정.md) 참고).
- **보고서 3**의 파일럿(N=100~200) 권고는 관리자 페이지의 판정 기준(응답 30개 이상만 판정, 보정은 50개 이상)과
  실제 규준 전환 기준(첫 응시 100명)으로 이어졌습니다.
