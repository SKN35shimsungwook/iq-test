# 06. 검증 기록

개발 중에 테스트·시뮬레이션·브라우저 실행으로 확인한 수치와, 그 과정에서 찾아 고친 문제들입니다.
실제 응시자 데이터가 아직 없으므로 **수치는 모두 가상 응시자(능력을 미리 정해 둔 시뮬레이션) 기준**입니다.

## 1. 정확도: 1·2·3차와 심층검사

참 능력을 아는 가상 응시자 150명(모드별)으로, 추정한 점수가 실제 능력과 얼마나 차이 나는지(RMSE, IQ 점수 단위) 쟀습니다.

| | 1차 | 1~3차 | 1~3차 + 심층 | 심층검사 문항 수 (5개 영역 합) |
|---|---|---|---|---|
| 빠른 검사 | ±6.6 | ±3.8 | **±2.8** | 약 28 |
| 정밀 검사 | ±3.4 | ±2.4 | **±2.0** | 약 20 |

심층검사 종료 기준 비교 (같은 방법):

| 종료 기준 | 빠른: 문항 수 / 오차 | 정밀: 문항 수 / 오차 | 결정 |
|---|---|---|---|
| ±4점, 최대 8문항 | 40 / ±2.6 | 36 / ±2.1 | 거의 항상 최대까지 가서 너무 김 |
| **±5점, 최대 6문항** | **28.5 / ±2.8** | **20 / ±2.0** | **채택** — 문항 30~45% 감소, 정확도 거의 같음 |
| ±5점, 최대 5문항 | 24 / ±2.8 | 19.6 / ±2.2 | |
| ±4.5점, 최대 6문항 | 30 / ±2.7 | 25.3 / ±2.3 | |

## 2. 신뢰도 (시뮬레이션 300~400명)

| 지표 | 값 |
|---|---|
| 동형 검사 신뢰도 (1·2차 종합 점수 상관) | 0.87 ~ 0.90 |
| 영역 주변 신뢰도 — 정밀 검사 | 0.64 ~ 0.78 |
| 영역 주변 신뢰도 — 빠른 검사 | 약 0.5 (영역 4문항이라 "참고용"으로 표시하는 근거) |
| 심층검사 영역별 평균 문항 수 / 최종 오차 | 4.5 ~ 5.8문항 / ±5 ~ 6점 |

## 3. 문항 분석이 문제 문항을 찾아내는가

가상 응시자 400명에게 문항 12개의 참 난이도를 일부러 크게(±2.5) 틀어 놓고 관리자 분석을 돌렸습니다.

| 판정 기준 | 응답 30개 이상인 틀어 놓은 문항 탐지 | 그 밖에 경고된 문항 |
|---|---|---|
| 차이 > 0.15 | 5 / 5 | 12개 (표본이 작을 때 우연한 차이) |
| **차이 > 0.15 이고 \|z\| > 3 (채택)** | **4 / 4** | **6개** (시뮬레이션이 모든 문항 난이도를 ±0.3씩 흔들어 둬서 일부는 실제 차이) |

응답이 30개 미만인 나머지는 "데이터 부족"으로 판정을 보류했습니다 (의도된 동작).

## 4. 검사지 구성 점검

| 점검 | 결과 |
|---|---|
| 검사지 시뮬레이션 (모드 2 × 500 × 3차) | 길이·유형 제한·차수 간 비중복 모두 위반 0건 |
| 같은 정답 단어·같은 제시어·같은 문제 문장 (언어 96문항) | 0건 |
| 동형 문항끼리 완전히 같은 경우 | 0건 |
| 난이도별 평균 예상 정답률 (유동추론·언어·수리·시공간) | 1~4단계 모두 약 0.85 → 0.65 → 0.45 → 0.25로 단조 감소 |
| 정답 위치 A~D (4지선다 전체) | 수정 전 28/75/58/43 → **수정 후 95/103/101/103** |
| 생성 슬롯 47개 × seed 80개 | 모두 유효 (보기 4개 서로 다름, 정답 1개, 정답 위치 고르게) |
| 숫자 문제 답 유일성 | 수 행렬·연산 기호 전 문항 × 26동형이 약 650개 규칙 검사 통과 |
| 수열 답 유일성 | 수열 24문항 모두 다른 규칙과 답이 갈리지 않음 (수정으로 바뀐 문항 0개) |

## 5. 실행 환경 점검

| 점검 | 결과 |
|---|---|
| 자동 테스트 | **87개 통과** |
| 실제 Postgres (PGlite) — `scripts/check_db.py` | 12단계 전부 통과 (접속, 테이블·RLS, 저장·덮어쓰기, 진행 복원, 완료, 차수·본 문항, 규준, 분석) |
| Postgres에서 앱 전체 | 응시, 새로고침 후 이어 풀기, 관리자 페이지 ("저장소: Postgres") 동작 |
| `requirements.txt`만으로 새 가상환경 | Streamlit 1.65에서 테스트 통과, 응시·타이머·작업기억 동작 |
| 브라우저 전 과정 | 빠른 검사 1차 → 2차 → 3차 → 심층검사 → 차수별 탭 결과까지 실제로 풀어 확인 |
| 모바일 폭 (375px) | 문제 그림 축소, 보기 2×2 배치 |

## 6. 찾아서 고친 문제

| 찾은 경로 | 문제 | 수정 |
|---|---|---|
| 브라우저 | 시작 화면 표에 숫자·글자가 섞여 서버 오류 로그 | 모두 글자로 |
| 브라우저 | 처리속도 90초가 "1분"으로 표시 | 시간 표시 함수 수정 |
| 리뷰 | 조사 오류 ("2을 곱하는", "회색색", "위을 향합니다", "힘가") | 숫자·단어 뒤 조사 처리 |
| 브라우저 | `st.html`이 SVG를 지워 문제 그림이 안 보임 | base64 이미지로 |
| 브라우저 | 새로고침하면 검사가 사라짐 | 진행 상태 DB 저장 + URL 세션 복원 |
| 스트레스 테스트 | 종이 접기 오답이 3개가 안 되는 경우 | 오답 후보 추가 |
| 스트레스 테스트 | 세 번 접을 때 펼친 위치가 틀림 (전체 중심 기준으로 대칭) | 접기 직전 종이 중심 기준으로 |
| 점검 | 정답 위치 쏠림 | 슬롯마다 정답 위치 순환 |
| 점검 | 작업기억 새로고침으로 숫자 다시 보기 | 0점 처리 |
| 점검 | 타이머 0:00 정지 가능성 | 만료 신호 재전송 |
| 점검 | 응답 중복 저장 가능성 | 덮어쓰기 |
| 브라우저 | "처음으로" 버튼 무반응 | 처리 순서 수정 |
| 시뮬레이션 | 정답 개수 기반 라우팅이 47%를 어려운 묶음으로 | 능력 기반으로 (이후 구조 개편으로 라우팅 자체는 제거) |
| 시뮬레이션 | 문항 경고가 우연한 차이에도 뜸 | 통계적 유의성 조건 추가 |
| 브라우저 | 작업기억 키패드에서 1~4를 누르면 답이 사라짐 | 키보드 리스너 정리 |
| 리뷰 | 심층검사 문항만으로 점수를 내 왜곡 (69 vs 65) | 항상 1~3차와 합쳐 계산 |
| 배포 | 푸시 후 `ImportError` | Streamlit Cloud 부분 재로딩 → Reboot (코드 문제 아님) |
| **사용자 제보** | 수 행렬이 a²+b와 a×(b+1) 두 규칙으로 풀리고, 후자의 답이 보기에 없음 | 같은 수 금지, 예시 3줄, 약 650개 규칙과 비교 |

## 7. 아직 검증하지 못한 것

- **실제 사람의 응답**: 모든 수치는 가정 문항 모수와 가상 응시자 기준입니다. 실제 응답이 쌓이면 관리자 페이지로 다시 확인해야 합니다.
- **처리속도 기준값**(평균 40·SD 12)은 근거 없는 가정입니다.
- **타당도**(다른 지능검사 점수와의 상관)는 측정하지 않았습니다.
- 수열 문제는 수학적으로 다른 규칙이 항상 있을 수 있어, 흔한 규칙 범위 안에서만 답의 유일성을 보장합니다.
