# 05. 개발자 가이드

## 1. 실행

```bash
pip install -r requirements-dev.txt
streamlit run streamlit_app.py              # http://localhost:8501
python -m pytest -q                         # 테스트
python scripts/validate_items.py --strict   # 문항은행 검증
python scripts/render_review.py             # 문항 검토 HTML → review/items_review.html
```

## 3. 핵심 개념

### 슬롯과 동형 문항
- **슬롯 ID** = `영역-유형-난이도` (예: `gf-matrix-3`). 난이도 1 쉬움 · 2 보통 · 3 어려움 · 4 매우 어려움
- **문항 ID** = 슬롯 + 동형 문자 (예: `gf-matrix-3d`). 4지선다 슬롯은 동형 **6개 이상**
- 영역·유형·난이도는 슬롯 ID에서 자동으로 채워지므로 문항 JSON에 쓰지 않아도 됩니다.
- 영역별 슬롯 수: 유동추론 19 · 언어 16 · 수리 16 · 시공간 16 · 작업기억 16 · 처리속도 1 = **84슬롯, 419문항**

### 검사 구성표 (`BLUEPRINT`)
1·2·3차는 모두 같은 고정 구성이고 쉬운 문제부터 놓입니다. 심층검사는 영역의 **풀(pool) 전체**에서 고릅니다.

| 영역 | 정밀 (쉬움 1 · 보통 3 · 어려움 3 · 매우 어려움 1) | 빠른 (난이도 1~4 하나씩) | 제한시간 정밀/빠른 |
|---|---|---|---|
| 유동추론 | sequence1 matrix2 analogy2 odd2 transform2 matrix3 odd3 transform3 sequence4 analogy4 | sequence1 matrix2 transform3 analogy4 | 9분 / 4분 |
| 언어 | category1 synonym2 analogy2 antonym2 synonym3 completion3 category3 analogy4 | category1 synonym2 completion3 analogy4 | 5분 / 2분 30초 |
| 수리 | data1 series2 operator2 applied2 number_matrix3 series3 applied3 number_matrix4 | data1 series2 applied3 number_matrix4 | 7분 / 4분 |
| 시공간 | rotation1 paper2 cube2 assembly2 rotation3 paper3 cube3 assembly4 | rotation1 cube2 paper3 assembly4 | 7분 / 4분 |
| 작업기억 | forward1 backward2 sorting2 spatial2 forward3 backward3 sorting3 spatial4 | forward1 sorting2 backward3 spatial4 | 문항별 |
| 처리속도 | symbol_coding2 (90초) | – | 90초 |

`validate_blueprint()`가 지키는 규칙: 슬롯이 풀 안에 있음, 난이도 오름차순, 정밀은 같은 유형 최대 2번, 빠른은 모두 다른 유형이고 난이도 1~4가 하나씩.

### 응시 상태 (`st.session_state.exam`)
dict 하나이며 DB `sessions.progress`(JSON)에도 저장되어 새로고침 후 복원됩니다.

| 키 | 뜻 |
|---|---|
| `kind` | `round`(1·2·3차) / `deep`(심층검사) |
| `domains`, `d`, `stage`, `i` | 영역 목록, 현재 영역·단계(intro/items)·문항 인덱스 |
| `items` | 영역 → 출제 문항 ID 목록 (심층검사는 고를 때마다 뒤에 붙음) |
| `answers`, `ms` | 문항 → 응답 문자열 / 누적 응답 시간(ms) |
| `deadline`, `entered` | 영역 마감 시각, 현재 문항 시작 시각 |
| `blurs`, `started` | 탭 이탈 수, 제시가 시작된 작업기억·처리속도 문항(새로고침 재시청 방지) |
| `prior`, `seen`, `estimates` | (심층검사) 1~3차 응답, 앞에서 본 문항, 영역별 최종 θ·SE |

|---|---|

## 4. 채점 수식 (`core/scoring.py`)

1. **문항 모수 (3PL)**: P(θ) = c + (1 − c) / (1 + e^(−1.7·a·(θ − b)))
   - 4지선다 c = 0.2, 작업기억 c = 0, a = 1
   - b는 평균 능력(θ=0)에서 정답률이 `expected_p`가 되도록: q = (p − c)/(1 − c), b = ln(1/q − 1)/1.7
   - `items/calibration.json`에 irt_a/b/c가 있으면 그 값을 씀
2. **능력 추정 (EAP)**: θ 격자(−4~4, 161점)에서 표준정규 사전분포 × 우도 → 사후 평균 = θ̂, 사후 표준편차 = SE.
   종합은 모든 문항을 하나의 일반 능력으로 함께 추정
3. **처리속도**: z = (점수 − 40)/12를 신뢰도 0.8의 정규 측정 모형으로 우도에 반영 (가정값, 데이터로 교체 예정)
4. **지수**: IQ(LTR Index) = 100 + 15·z (40~160), 백분위 = Φ(z), 90% 범위 = 지수 ± 1.645 × 15 × SE
5. **규준**: 같은 모드·1차·첫 응시·비시뮬레이션 세션이 100명 이상이면 z = (θ − 평균)/표준편차로 재표준화
6. **강점·약점**: 영역 지수 − 본인 영역 평균이 8점 이상이고 1.28 × SE보다 클 때만
7. **문항 정보량**: I(θ) = (1.7a)² · ((P − c)²/(1 − c)²) · ((1 − P)/P)

## 5. 심층검사 알고리즘 (`core/exam.py`)

```
for 영역 in [유동추론, 언어, 수리, 시공간, 작업기억]:
    θ, SE = EAP(1~3차 그 영역 응답 + 지금까지의 심층 응답)
    while True:
        if 문항 수 ≥ 6 또는 (문항 수 ≥ 3 이고 SE ≤ 0.33):  종료
        후보 = 그 영역 문항 중 앞 차수에서 안 본 것 (작업기억은 자극이 새로 정해지므로 재사용 허용)
        정보량 I(θ) 상위 6개 중 직전과 다른 유형 → 상위 3개 중 무작위 1개   # 노출 분산
        출제 → 응답 → θ, SE 갱신
```
- 영역 제한시간 6분(6문항 × 60초), 작업기억은 제한 없음, 처리속도 제외
- 결과는 심층 문항만으로 계산하지 않고 **항상 1~3차와 합쳐** 계산 (실력에 맞춰 고른 문항이라 단독 추정은 왜곡됨)

## 6. 문항 추가하기

### 6-1. 직접 쓰는 문항 (`items/gc.json`, `items/gq.json`)
```json
{"id": "gc-synonym-3g", "slot": "gc-synonym-3",
 "prompt": "'면밀하다'와 뜻이 가장 가까운 말은?",
 "choices": ["친밀하다", "치밀하다", "엄격하다", "은밀하다"], "answer": 1,
 "explanation": "…", "expected_p": 0.4}
```
- `answer`는 보기 인덱스(0~3). 정답 위치는 로드할 때 슬롯 안에서 A~D가 고르게 돌아가도록 자동 조정되므로 아무 데나 써도 됩니다.
- 수리는 `"params": {"verify": "20 / 0.08 - 200"}`를 넣으면 검증기가 계산 결과와 정답 보기가 일치하는지, 다른 보기와 겹치지 않는지 확인합니다.
- 오답은 "그럴듯한 실수"로 만듭니다 (형태가 비슷한 단어, 글자 그대로의 뜻, 할인율을 더한 값 등).
- 고칠 때는 `version`을 올립니다.

### 6-2. 생성기 슬롯 (`items/generated.json`)
```json
{"slot": "gf-matrix-4", "generator": "matrix", "forms": 6, "params": {"level": 4},
 "prompt": "빈칸(?)에 들어갈 알맞은 그림은?", "expected_p": 0.25}
```
- 동형 i번은 `seed = crc32("슬롯:i")`로 결정적으로 생성되고, `pick_variant`가 동형마다 다른 규칙 변형을 고릅니다.

| 생성기 | 단계별 내용 | 답 유일성 장치 |
|---|---|---|
| matrix | 1 규칙 1개 · 2 규칙 2개 · 3 규칙 3개 · 4 덧셈 규칙 포함 | 보기 균형 설계 (속성별 정답 값이 4개 중 2개에만) |
| sequence | 1 한 속성 주기 · 2 두 속성 · 3 세 속성 · 4 가속 회전/오르내림 | 균형 설계 |
| fig_analogy | 1 같은 모양 · 2 변환 1개 · 3 변환 2개 · 4 변환 3개 | A→B를 설명하는 다른 변환 조합이 C에 다른 답을 내면 폐기 |
| odd_one_out | 1 단일 속성 · 2 홀짝·꼭짓점 · 3 두 속성의 관계 | 다른 기준으로 보면 다른 도형이 튀면 폐기 |
| transform | 단계 = 기호 적용 횟수(1~4) | 빠뜨림·착각 결과가 정답과 겹치지 않게 |
| series | 1 등차·등비 · 2 2차·교대·피보나치 · 3 교대 연산·곱 · 4 이중 수열·계승형 | 다항식·점화식·교대 연산·홀짝 갈래·차이/비율 규칙 예측과 비교 (`series_predictions`) |
| number_matrix / operator | 2·3·4 / 1·2·3 단계 규칙 목록 | 예시 3줄, 두 수가 같은 줄 금지, 약 650개 규칙과 비교 (`unambiguous`) |
| data | 1 합계·증가량·평균 · 2 증가율·비율 | 동률 금지 |
| rotation | 칸 5·6·7·9, 한 칸 어긋난 오답 0~2개 | 회전 대칭 없고 거울상과 구별되는 조각만 |
| paper_fold | 접기 1·2·2·3회, 구멍 1~2개 | 접기 직전 종이 중심 기준으로 정확히 펼침 |
| cube_net | 1 1-4-1 긴 줄 · 2 1-4-1 · 3 그 밖의 전개도 · 4 마주 보는 짝 | 3D로 접어 면 법선 계산 |
| assembly | 3×3(쉬움은 칸 수 다른 오답 포함) · 3×3 · 4×4 · 5×5 | 회전으로만 맞는지 비교 |

## 7. 커스텀 컴포넌트 규칙 (`core/components.py`)

Streamlit Custom Components **v2**만 씁니다 (v1의 `components.html`·`Streamlit.setComponentValue` 금지).
- `data.token`이 같으면 화면을 다시 만들지 않아, 재실행돼도 진행 중인 애니메이션이 끊기지 않음
- **문서 전체에 거는 키보드·visibility 리스너는 인스턴스당 하나**, 화면에서 사라지면(`!el.isConnected`) 스스로 해제.
  남아 있으면 다른 화면의 키 입력에 반응해 엉뚱한 재실행을 일으킴 (작업기억 답이 사라지던 버그의 원인)
- 상태(`setStateValue`)는 재실행을 일으키므로 `started`처럼 꼭 필요한 것만
- 문제 그림은 `st.html`이 SVG를 지우므로 base64 `<img>`로

## 9. 알아 둘 것

- 커밋 메시지는 한국어 `<타입>: 무엇을` (예: `fix: …`, `feat: …`)
- Streamlit Cloud에서 여러 모듈이 한꺼번에 바뀐 푸시 뒤 `ImportError`가 나면 코드가 아니라 부분 재로딩 문제 → Reboot
- `st.switch_page`가 쿼리 파라미터를 지울 수 있어, 세션 ID(`?s=`)는 `streamlit_app.py`에서 매 실행마다 다시 붙임
- 결과 화면의 처리속도 기준(평균 40·SD 12)과 심층검사 기준(±5점·3~6문항)은 시뮬레이션 기반 가정값이며 `core/scoring.py`·`core/schema.py` 상수로 조정
