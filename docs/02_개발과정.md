## 2. 1단계: 뼈대

- 문항 스키마(`Item`), 검사 구성표, 문항은행 로더·검증기
- DB 계층: SQLAlchemy Core만 써서 SQLite·Postgres 공용. `sessions`(응시)와 `responses`(문항별 응답·응답 시간) 테이블
- 같은 브라우저의 재응시는 `is_first_attempt=False`로 표시해 규준 계산에서 제외
- 시작 화면: 검사 구성, 한계 고지, 동의 체크박스(기본 해제)
- 브라우저 확인 중 버그 2개 수정 (표에 숫자·글자가 섞여 Arrow 변환 오류 / 90초가 "1분"으로 표시)

## 3. 2단계: 문항 초안 → 1차 개편

### 3-1. 첫 초안 (62문항)
행렬 생성기(SVG 3×3, 규칙: 같음·증가·한 번씩 분배)와 블록 회전 생성기를 만들고, 언어·수리 문항은 직접 작성했습니다.
행렬 보기는 **균형 설계**를 썼습니다. 각 속성의 정답 값이 4개 보기 중 정확히 2개에만 나오게 해서,
"보기들에서 가장 많이 나온 모양"으로는 정답을 찍을 수 없습니다.

### 3-2. 사용자 피드백: "문제끼리 같은 걸 물어본다"
처음에는 "공통성 문항이 애매하다"로 잘못 이해했다가, 다시 물어 **중복 문제**라는 뜻임을 확인했습니다. 세 가지가 모두 해당했습니다.

| 중복 | 예 | 해결 |
|---|---|---|
| 한 검사에 같은 유형 반복 | 유동추론 10개가 전부 행렬 | 영역마다 유형 4~5개, 한 검사지에서 같은 유형 최대 2번 |
| 동형 a/b끼리 너무 비슷 | 둘 다 "개수 증가" 행렬 | 동형마다 다른 규칙 조합을 고르도록(`pick_variant`) |
| 영역끼리 겹침 | 수리 수열 ↔ 유동추론 규칙 찾기, 언어 삼단논법 ↔ 추론 | 경계 재정의: 유동추론 = 도형만, 수리 = 숫자만, 언어 = 어휘·지식, 삼단논법·거울상 유형 삭제 |

### 3-3. 사용자 피드백: "한 항목당 못해도 30개 이상은 있어야"
문항 풀 기준을 **영역당 30개 이상, 슬롯당 동형 6개 이상**으로 정했습니다.
"한 번 응시의 정확도는 푸는 문항 수와 변별력이 좌우하고, 풀이 크면 재응시·노출 방지·문항 분석에 유리하다"는 점을 함께 설명했습니다.
빠른 검사(약 15분)·정밀 검사(약 35분) 두 모드도 이때 생겼습니다.

새 생성기 11종: 도형 시퀀스, 도형 유추, 다른 도형 찾기, 도형 변환 기호 / 수열, 수 행렬, 연산 기호, 자료 해석 /
종이 접어 구멍 뚫기, 정육면체 전개도(3D로 접어 면의 법선을 계산), 조각 맞추기. 결과 **213문항**.

- 적응형 출제에서는 단순 정답률이 왜곡되므로 **"그 문항을 본 사람들의 능력으로 예측한 정답률"과 비교**하는 문항 판정

## 10. 3차 개편 (`9f5ebcf`): "1·2·3차 검증"의 진짜 의미

배포 후 화면에 "1단계·2단계"가 보이자 사용자가 지적했습니다:
**원하던 건 영역 안 단계가 아니라, 검사 전체를 1차·2차·3차로 다시 풀어 검증하는 것**. 다시 물어 정리한 결과:

- 1·2·3차는 **모두 같은 고정 구성**(난이도 1~4 고르게, 쉬운 문제부터). 영역 안 적응형은 제거
- 차수마다 결과, 다음 차수는 선택, 빠른·정밀 모두 3차까지
- 사용자 제안: **3차 뒤 "심층검사"** — 1~3차로 추정한 실력에 맞춰 난이도를 정밀하게 조정 → CAT로 구현
- 심층검사 종료 기준을 시뮬레이션으로 비교해 **±5점·최대 6문항**으로 결정 (±4점·8문항 대비 문항 수 30~45% 감소, 정확도는 거의 같음)

이어서 결과 화면을 **차수별 탭 + 최종 결과 탭**으로 바꾸고, IQ를 맨 위에 범위와 함께 크게 표시했습니다.
심층검사 문항만으로 점수를 내면 왜곡되므로(실력에 맞춰 고른 문항이라) 항상 1~3차와 합쳐 계산합니다.

### 이때 찾은 중요한 버그
작업기억 숫자 키패드에서 **1~4를 누르면 답이 사라지는** 문제. 앞 영역 보기 타일의 키보드 리스너가 화면에서
사라진 뒤에도 남아 1~4 키에 반응하며 엉뚱한 재실행을 일으켰습니다. 리스너를 인스턴스당 하나로 하고,
화면에서 사라진 뒤에는 반응하지 않게 고쳤습니다.

### 배포 중 오류
푸시 후 `ImportError`가 났습니다. 코드 문제가 아니라 Streamlit Cloud가 바뀐 파일 일부만 다시 읽어
옛 `core/schema.py`가 메모리에 남은 것이었고, **Reboot app**으로 해결했습니다.

## 11. 숫자 문제 답 중복 수정 (`93851b1`)

사용자가 찾은 문제: `8,8→72 / 4,4→20 / 7,6→?`. 의도는 a²+b(답 55)였지만 예시가 모두 "첫째=둘째"라
a×(b+1)(답 49)로도 풀렸고, 49는 보기에 없었습니다.

- 예시·질문에서 두 수가 같은 줄 금지, 예시를 2줄 → 3줄
- 비교 규칙을 출제용 십여 개에서 **약 650개 그럴듯한 규칙**으로 넓혀, 모두 같은 답일 때만 출제 (연산 기호에도 적용)
- 수열도 다항식·점화식·교대 연산·홀짝 갈래·차이/비율 규칙과 비교해 답이 갈리면 숫자만 다시 뽑게 함
- 사용자 요청에 따라 **규칙과 난이도는 그대로**, 숫자 조합만 바뀜. 기존 수열 24문항은 이미 모두 답이 하나라 바뀐 것 없음
